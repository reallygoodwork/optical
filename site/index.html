Optical
A Really Good Work Inc. project

One scene in. Every asset your brand needs out.

Write an asset once, as JSON. Optical renders it as a PNG, GIF, MP4 or PDF, in your brand, fast enough for an agent to try ten versions.

01 The problem

Brand work still gets made one size at a time.

A launch needs a story, a square, a banner, a share card, a GIF and a PDF. Someone builds the same thing six times. Then the copy changes and they do it again.

Agents can write the copy now. They can’t make it look like you. That part still lands on a designer’s desk, one file at a time.

02 How it works

Write the scene. Get the files.

  1. 01Describe the asset as layers: text, images, video, shapes, even real HTML. Each layer gets timing and motion.
  2. 02Point it at your brand. Colours, fonts and type styles come from tokens, not hex codes.
  3. 03Optical draws every frame in Rust. No headless browser.
  4. 04Out come the formats and sizes you asked for, all in one call.

Render it as ["mp4", "gif", "png"] in ["instagram-story", "square", "og"] and you get nine files back.

03 The reels

Three sizzle reels. No footage.

Made for Demons, a test brand with a crew of mascots. Each reel is one JSON file cut to a 120 BPM beat: kinetic type, colour wipes, bobbing characters, ticking counters.

Beat cuts
Shots, wipes and word slams land on every half second.
Real CSS
The conveyor and the counters are HTML with @keyframes, driven by the scene’s clock.
Brand rules
No mascot on its own colour. Three at most. Caps only on stickers. The validator checks contrast on every shot.

Why it’s cheap to run.

Most of a brand video doesn’t move. A logo sits still for two seconds. A headline holds. So Optical only draws what changed.

Frame reuse
Each frame gets a fingerprint before it’s drawn. Same fingerprint, same pixels, no work.
Video in the encoder
Background footage is scaled and zoomed by ffmpeg, under a see-through overlay. That alone cut one render’s CPU by 88%.
Drafts
Preview at half size as a contact sheet. Render the finals once.
The last tune-up
28% faster, 32% less server CPU, files 2% smaller.
06 Device or server

Their device when it can. Your server when it should.

The same scene renders in the browser with WebAssembly and WebCodecs, or on Node with ffmpeg. Same pixels either way, so you pick by cost, not by look.

Device
Stills, GIFs and short clips the browser can encode, under a size budget. Costs you nothing.
Server
Long video, missing codecs, agents and scripts. Runs on Vercel or any Node box.
Fallback
If the device can’t finish, the server picks it up. The person waiting never knows.
Long video
Split into chunks, render them in parallel, join them in one pass.
07 For agents

Built for agents to drive.

Models are good at JSON and bad at pixels. So the agent writes the scene, Optical does the drawing, and every call hands back a picture the model can check.

get_brand
Tokens, type styles, assets and sizes. Start here.
preview
The whole timeline as one contact sheet. One image to look at, not a video.
edit_scene
Small changes by layer id. No rewriting the scene to move a logo.
render
Every format and size in one call.
validate
Names the mistake and where it is: a token that doesn’t exist, timing that can’t happen, text you can’t read.

Plug it into Claude, Cursor or anything that speaks MCP with optical mcp --brand brand.json. Or call the same tools from your own code.

Why “Optical”
Before computers, film titles and effects came off an optical printer. Its operator layered footage, mattes and type into one finished negative, frame by frame, the same way every time. Same job, new machine.
